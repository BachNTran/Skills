# ADR-0001 — Invisible, self-enforcing, fully-traceable AI dev workflow

## Status

Accepted (2026-06-17). Drives a phased redesign of this Skills repo. Individual
phases may spawn their own ADRs as boundaries are locked.

## Context

The current skillset (`/workflow /idea /triage /feature /implement /cleanup /onboard
/diagram /sound-notify`) is mature: lazy-loaded templates, a bidirectional REQ↔test
matrix, ADRs, and a hand-authored Mermaid skill. It works, but three gaps remain:

1. **The developer must remember the workflow.** Which skill, which phase, when to
   sync — all carried in the human's head. That cognitive load defeats the point of an
   assistant.
2. **Traceability is one-way and shallow.** Like the rest of the industry (GitHub
   Spec-Kit, AWS Kiro), the pipeline runs spec → plan → tasks → code. The reverse link
   — from a line of code back to the test that proves it, the requirement it serves, the
   rationale for that requirement, and the *decision the developer converged on long
   ago* — is informal at best.
3. **The project does not get smarter.** Preferences, design taste, domain facts, and
   corrections are not captured or replayed, so the agent re-learns the developer every
   session.

The developer's north star is a **bottom-up walk**: point at any functionality and
receive `code → tests → test-plan rationale (happy path + failure modes + how the design
handles each) → requirements (with why-needed / why-not) → the decision points`, with
**accountability resting on the human** (decisions are joint convergences, not
agent-proposals rubber-stamped), and **none of it requiring the developer to remember
the workflow**.

## Decision

Evolve the skillset into an **intent-routed, self-enforcing, fully-traceable** workflow.
Locked design decisions (from the 2026-06-17 grill):

### 1. Front door = intent, not commands
A thin always-on **router** (in `AGENTS.md`) classifies natural-language intent
(`add / change / remove / idea / explain / why / complaint / config`) and runs the right
phase. Slash commands remain as internal modules and manual escape hatches; the developer
never needs to type one.

### 2. Autonomy is a dial set by project criticality
Three tiers, default **STANDARD**, declared per project in `PROJECT_CONTEXT.md`,
overridable per feature in its `BRIEF.md` (with a reason):

| Tier      | Developer involvement                     | Agent role                         | Trace depth          |
|-----------|-------------------------------------------|------------------------------------|----------------------|
| EXPLORE   | Grill the idea, then step back            | Ships autonomously                 | Light                |
| STANDARD  | Approve PRD + test plan + slice plan      | Implements solo                    | Full                 |
| CRITICAL  | Review every slice, diff, and line        | Grunt work + second eye only       | Full + rationale forced |

On a fresh project with **no config**, the agent runs a short **config grill**, proposes
a plan, and saves the config for future sessions. Hooks enforce the gates deterministically
(e.g. CRITICAL blocks auto-merge until the developer's review is recorded) so safety can
never be skipped by a forgetful model.

### 3. Traceability spine
Stable IDs live in artifact **frontmatter**; the source of truth stays in the artifacts;
a derived **TRACE index is regenerated by a milestone hook** — never hand-edited.

```
grill convergence ──births──▶ REQ-007 (EARS + inline why/why-not) ──from──▶ DEC-014 (informal, supersedable)
                                  │
                                  ├─proven-by─▶ TC-012 (happy) , TC-013 (failure mode)
                                  └──covered-by──────────────────────────────────────▶ dma.c  // @covers REQ-007
```

- **Decision record (`DEC-###`):** informal prose body + stable ID; supersedable (a
  revision creates a new DEC that supersedes the old, with reason).
- **Requirement (`REQ-###`):** EARS phrasing + inline rationale (why / why-not-broader /
  non-goal) + `from: DEC-###`.
- **Test case (`TC-###`):** names the REQ it proves and the level (unit/integration/e2e);
  failure-mode cases state what fails and how the design handles it.
- **Code:** `// @covers REQ-###` annotations tie implementation regions to requirements.
- **`TRACE.md` (generated):** markdown tables + bidirectional relative links + a Mermaid
  system/subsystem map + an **orphan report** (REQ with no test, test with no REQ, code
  with no REQ). The orphan report is what makes "tested here, here, and here" *provable*.

### 4. The "gets smarter" loop
- **SessionStart hook** silently injects a brief digest (active preferences + current
  project state) via `additionalContext`.
- **Milestone hooks** (slice merged, feature closed) capture decisions, regenerate the
  trace, and reconcile preferences.
- Memory captures four kinds: **design preferences, decision rationale, glossary/domain
  facts, workflow corrections.**

### 5. Complaint → revision loop
On detected dissatisfaction the agent confirms, then logs `CMP-###`, traces *why* the
thing was built that way (walking the DEC chain), proposes amendments to PRD/test/decision,
and **asks whether to propagate the new pattern/preference project-wide and to other
features.** Propagation is what compounds the developer's taste into the project.

### 6. Accountability
No rubber-stamp approvals. Decisions are recorded as **joint convergences from grilling**;
the DEC record is the evidence the human shaped the reasoning. The human owns the system
because the human shaped every decision, and the trace proves it.

### 7. Context is project-local; skills may be global
Skills (behavior) can be installed globally (`~/.claude/skills/`) and shared across projects.
**Project knowledge — criticality config, domain/knowledge-base, preferences, decision ledger,
and the trace index — is always written into the project, never the global skills location.**
A globally-installed skillset used in an un-bootstrapped project detects the missing scaffold,
bootstraps it locally, and runs the config grill. Each project therefore accumulates its own
smarts independently, and a global skills upgrade never disturbs a project's history.

### 8. Token posture
Always-on footprint stays lean: thin router + one-line skill hints + active-preference
digest. Full skill bodies, the trace index, and decision/preference history all lazy-load.
The README token-measurement table remains the discipline.

## Consequences

**Positive**
- The developer states intent; the system routes, records, traces, and learns.
- Any functionality is auditable bottom-up, with provable (not claimed) test coverage.
- Safety-critical projects get deterministic, hook-enforced review gates.
- The project compounds the developer's design taste over time.

**Negative / costs**
- More moving parts (router, hooks, trace generator, memory files) to build and maintain.
- Hooks add a hard dependency on Claude Code's hook system for the self-enforcement
  guarantees; AGENTS.md-only agents (Codex, Cursor) get the conventions but not the
  enforcement.
- Auto-generated artifacts (TRACE.md, system map) must be regenerated, not edited, or they
  drift — requires discipline and a clear "generated, do not edit" marker.

## Build plan (each phase ships independently)

| Phase | Delivers | Rationale |
|-------|----------|-----------|
| **0** | Criticality tiers + init config grill + `PROJECT_CONTEXT` schema | Foundation; gates everything |
| **1** | DEC ledger + EARS REQs w/ inline rationale + trace IDs in frontmatter (convention) | The data model |
| **2** | Trace-index generator + milestone hook → `TRACE.md` (tables + links + Mermaid + orphan report) | **Unlocks the bottom-up walk** |
| **3** | Preference/memory files + SessionStart inject + reconcile hook | The "gets smarter" engine |
| **4** | Intent router → invisible entry + batch-grill refactor | Removes "remember the skill" |
| **5** | Complaint → revision + pattern propagation | The compounding loop |
| **6** | Auto system/subsystem Mermaid + token-budget pass + README | Polish & measure |

Phase 2 is the highest-leverage single deliverable.
